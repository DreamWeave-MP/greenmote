Errors are printed as `error:` and one message, and the command exits with 1. Nothing below is a
reason to edit a plugin by hand.

## Finding your setup

**`error: failed to read OpenMW configuration from autodetected locations or the default user config path`**

No `openmw.cfg` was found where OpenMW looks, and the default user one could not be read either.
Run OpenMW's launcher once, or name your cfg: `greenmote --openmw-cfg /path/to/openmw.cfg convert`.
The message ends with both errors and the path it tried.

**`Greenmote could not use the requested OpenMW configuration`** and `Use this path? [y/N]`

`--openmw-cfg` names neither a file nor a folder holding `openmw.cfg`. Answer `y` to use the
default user one instead. Anything else ends with `error: no OpenMW configuration selected`.

**`error: openmw.cfg has no content files`**

The cfg that was found has no `content=` lines: it is not the one your load order is in, or it
chains to it with a `config=` line that points somewhere else. Pass the right one with
`--openmw-cfg`.

**`error: active content file X was not found in the VFS`**

Unclip reads every content file to know the world, and one listed in `openmw.cfg` is in none of
the data folders. Fix the load order: remove the line, or add the folder that holds the file.
Convert skips such a file instead.

## greenmote.toml

**`error: config file PATH does not exist`**

`--validate-config` checks an existing file and does not create one. Run a convert without
`--dry-run`, or open the GUI, to write the defaults.

**`error: TOML parse error at line ...`**

The file is not valid TOML. The message points at the line. The GUI offers to move the file aside
and write the defaults.

**`error: invalid grass id filter: ...`**, `invalid occluder id filter`, `invalid road texture path filter`,
or a regex error from convert

A pattern is not a valid regular expression. The message quotes it. A literal `.`, `(` or `[`
needs a backslash, and a backslash in a double-quoted TOML string is written `\\`.

**`error: sink (6) must not exceed max_sink (4)`**, `max_tilt must be at most 90 degrees`, and
similar

An unclip number is out of range. [greenmote.toml](@/docs/configuration.md#unclip) gives each
range.

**`warning: ignoring unknown [unclip] keys in PATH: ...`**

Settings from an older version, or a typo. They are ignored; the GUI drops them when it saves.

## Convert

**The plan says `matched records: 0`**

No static or activator in the loaded plugins matched your patterns, or every plugin was ignored:
check `loaded plugins` too. A real run would write two empty plugins. Check `grass_ids`,
`exclude`, `ignored_plugins` and `--ignore`.

**`error: missing required meshes in OpenMW VFS:`** and a list

A converted static's mesh is in none of the data folders or archives. Nothing was written. The
mod that provides the mesh is missing or disabled, or its archive has no `fallback-archive=`
line. Fix the load order, or exclude that static by ID.

**`[ WARNING ]: Plugin PATH could not be loaded: ... Continuing.`**

A content file could not be parsed. It is left out of the conversion; any grass it places is not
converted.

**`error: plugins contributed matched records but could not be loaded for cell scanning: ...`**

A plugin that defines a matched static loaded for planning but failed when its cells were read.
The plugin is damaged; ignore it with `--ignore` or fix it.

**`error: groundcover output needs N masters, but TES3 reference indices only support 255`**

Grass is placed by more than 255 plugins, more than one plugin can name as masters. Ignore some
with `ignored_plugins`, or convert in two passes with different `--output` folders.

**`error: refusing to auto-enable outputs in DIR because it is not data-local or a configured data directory`**

`--auto-enable` would enable plugins OpenMW cannot find. Nothing was written. Write to
`data-local` or a `data=` folder, or add `DIR` to `openmw.cfg` first.

**The grass is gone in game**

Both plugins are enabled but groundcover is off: set `enabled = true` under `[Groundcover]` in
`settings.cfg`. Or `deleted_groundcover.omwaddon` is enabled and `groundcover.omwaddon` is not a
`groundcover=` line.

## Unclip

**`error: unclip requires --plugin or [unclip].plugin in greenmote.toml`**

Say which plugin: `greenmote unclip --plugin Rem_AI.esp`.

**`error: target plugin X was not found as a file or VFS entry`**

`X` is not a file, and no data folder has a plugin by that name. Give its path.

**`error: X was generated by greenmote convert and cannot be unclipped`**

Convert rebuilds `groundcover.omwaddon` from your load order on every run, so fixes written into
it would be lost. Unclip the grass mods that are `groundcover=` plugins instead.

**`WARNING: N refs were skipped because their mesh could not be loaded`**

The target's grass meshes are not in the data folders. For a mod that is not enabled yet, unclip
looks near the plugin for them; if they are further away, add the mod's folder as `data=`.

**`WARNING: N static occluder meshes could not be loaded`**

Statics in the load order whose meshes are missing. Grass clipping into them cannot be found. If
they are not editor markers, a mod in the load order is missing files.

**`Cells: ... N missing terrain`**

The target places grass in cells no content file has terrain for: a landmass mod it was made for
is not in your load order. References there are skipped with `skip_no_terrain`.

**Many `delete_road` or `delete_outside_cell`**

Expected for plugins generated without road exclusion, and for generators that let grass spill
across cell edges. Turn road-delete off with `--actions` if your roads should keep their grass.

**Many `fix_ground` on a plugin that looks fine in game**

The generator buried its grass deeper than `max_sink` and `max_sink_fraction` allow. Raise them;
[tuning](@/docs/unclip.md#tuning) explains each.

**`error: verification failed for ref ...`** or `written plugin ... does not load back`

The rewritten plugin did not read back as planned. The previous file is in `<plugin>.bak` and the
first original in `<plugin>.greenmote-original`. Please
[report it](https://github.com/DreamWeave-MP/greenmote/issues) with the plugin's name.

**Undoing unclip**

Copy `<plugin>.greenmote-original` over the plugin. It is the plugin as it was before the first
`--write`, whatever ran since.
